# Extending LocalMind

The short answer: **there is no plugin system, and adding one would break the
security properties this app is built around.** This page says what you can
change without one, and what a plugin would have cost.

## Why there is no runtime plugin API

A plugin system for this app would need one of two things:

1. **`eval` or `new Function` on downloaded code.** The CSP forbids
   `unsafe-eval`, deliberately: a single injected script would then be able to
   read every chat and every decrypted vault in the tab. Removing that rule to
   support plugins would trade the app's main promise for an extension point.
2. **Loading third-party scripts at runtime.** `script-src 'self'` allows only
   code shipped in the build, and the service worker plus the offline kill switch
   assume that. Any remote script is also a supply-chain dependency nobody
   reviews.

Neither is worth it for an app whose pitch is "nothing leaves this tab". The
alternative used here is **data-driven configuration**: the parts you would
reasonably want to change are data files or small modules you edit in a fork, and
they are all covered by tests and by the build-time checks.

## What you can change without touching the app loop

| You want to                                        | Edit                                                                                                                                      | Guardrails                                                                                                                            |
| -------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Add or reorder models in the picker                | `src/engine/model-catalogue.json` (regenerated by `npm run models:sync`), or add a curated entry in `src/engine/model-license-table.json` | `npm run models:licenses` reports how many entries are unverified; unknown licences require acceptance with a model-card link at load |
| Change which model the device recommendation picks | `src/engine/device.ts` (`lightestGpuModel`, the VRAM fit check)                                                                           | `tests/unit/device.test.js`                                                                                                           |
| Tune retrieval, chunking, thresholds               | `src/rag/config.ts` (`RAG`), `src/rag/confidence.ts`                                                                                      | `tests/unit/rag*.test.js`, `tests/evals/cases.json`                                                                                   |
| Change the built-in assistant's replies            | `src/chat/replies.ts`, `src/coder/programs.ts`                                                                                            | `tests/unit/replies.test.js`; the rule engine is the default experience, so its wording is user-visible                               |
| Add a language for the coder mode                  | `src/coder/languages.ts`, `src/coder/grammars.ts`                                                                                         | highlight.js grammars are registered statically so nothing is fetched at runtime                                                      |
| Change the context window or output budget         | `src/context.ts` (`BUILTIN_CONTEXT_LIMITS`, `generationOutputBudget`)                                                                     | `tests/unit/context.test.js`                                                                                                          |
| Add a UI surface                                   | `index.html` + `src/app.ts` + `src/style.css`                                                                                             | Playwright specs must go through `open()`; new focusable elements need a visible `:focus-visible` ring and an accessible name         |

Every one of these is a code change in your fork, reviewed by tests and by CI,
rather than a script the app trusts at runtime. That is the trade: contributors
need a checkout, users never run code they did not download with the app.

## If you are adding a feature, these are the rules

1. **No new network origins.** `connect-src` in the CSP lists Hugging Face hosts
   and `raw.githubusercontent.com`. A feature that needs another host is a
   conversation about privacy, not a config change.
2. **No new runtime dependency without a licence check.** `npm run deps:licenses`
   must stay green, and the payload budget in `src/config.ts` is measured by
   `npm run check:size` (currently 264 kB gzip).
3. **Never write plaintext when a vault exists.** `saveConversation` fails closed;
   do not add a fallback path. Encryption happens before the IndexedDB transaction
   opens, because awaiting WebCrypto inside a live transaction lets it auto-close
   in some engines.
4. **Anything rendered from model or document text goes through the sanitizer.**
   Trusted Types is enforced; `innerHTML` will not accept a plain string.
5. **A new Worker owns its own GPU objects.** Never call `buffer.destroy()` on
   memory WebLLM created; unload the engine and terminate the worker.
6. **Document the limitation in the same pull request.** The README and
   `docs/threat-model.md` list what is not protected; a feature that quietly
   narrows a guarantee is a bug in the documentation.

## A worked example: a second embedding model

The retrieval pipeline takes its model name, dimension, and limits from
`src/rag/config.ts`. To run a different embedding model locally:

1. Point `RAG.embeddingModel` at the Transformers.js model id you want.
2. Update `RAG.embeddingDimension` to match it, and delete existing vectors in
   Settings (the store records the dimension it was built with and refuses
   mismatched writes).
3. Run `npm run test -- tests/unit/rag.test.js` and the retrieval evals in
   `tests/evals/cases.json`; the confidence gate's term thresholds assume the
   MiniLM score distribution, so re-tune them if the scores shift.
4. Add the model's licence to `src/engine/model-license-table.json` if it is not
   Apache-2.0/MIT, so the licence gate can show it to users.

That is the whole "plugin" story: a config edit, a re-index, and tests. It keeps
the app static, auditable, and honest about what it downloads.
